# Device Mirror 使用与构建

## 运行环境

打开 `Device Mirror.app`。应用约 65 MB，支持 Apple Silicon / macOS 26，内含 adb、scrcpy、原生 Swift 控制服务和动态库，可移到任意可读的本地目录使用。日常运行不依赖源码、Homebrew 或 Python。

iOS USB 操控和模拟器需要完整 Xcode，连接时通过本机 XCTest 启动控制组件；真机还需要开发团队及设备测试认证。Android 和 iOS USB 观看镜像使用应用内组件及 macOS 系统功能。

构建产物采用本地签名。公开分发前需要完成 Developer ID 签名、公证及目标系统兼容性验证；Intel 与其他 macOS 版本尚未验证。

## Android

1. 用支持数据传输的 USB 线连接设备，开启 USB 调试，在设备上允许调试授权。
2. 在 Android 页选中设备，设置画质、帧率、音频及保持唤醒选项，再点“开始投屏”。这些选项在下次启动该设备时生效。

窗口顶部提供返回、主页、最近任务、音量、电源和通知按键。画面内支持点击、滑动、滚轮和键盘，每台设备独立设置，输入目标固定为该窗口所属设备。

### 文字与按键

先点击设备中的输入框，再点投屏窗口顶部的“发送文本”，在面板中输入或粘贴文字后点“发送”；也可使用按键栏下方的文字栏。文字直接提交到当前输入框，支持中文和表情，保留设备剪贴板。首次发送时，应用自动安装约 13 KB 的 Device Mirror 文本输入组件；需要在设备上允许 USB 安装。每次发送临时切换到该组件，完成后恢复原输入法及启用状态。组件没有桌面入口、联网权限和剪贴板访问代码，命令接收仅允许 adb shell／系统权限。

普通键盘输入使用单一文字提交路径；本地文字栏和发送面板中的草稿只在点击“发送”时提交。文本与后续回车、退格、点击按同一设备的命令队列执行。安全输入框或应用自有编辑控件可能拒绝输入；未找到焦点时会提示先点击设备输入框。提交输入时使用“按键”菜单中的回车；该菜单也提供退格、Delete、Tab、Escape 和方向键。

### 日志

每次投屏自动保存 `mirror.log`。系统日志可在启动前勾选“投屏时记录系统日志（logcat）”，也可在设备列表选中活动设备后点“记录系统日志”或“停止记录”。

日志位于 `~/Library/Logs/DeviceMirror/android-<设备标识>-<会话标识>/`。每次录制生成独立的 `logcat-<标识>.log`，保留设备现有日志缓冲区。窗口“日志”定位运行日志，设备列表“此设备日志”打开会话目录。关闭投屏会停止该设备录制；持续录制会占用本机磁盘。

### 画面与滑动

画面保持设备比例，贴合窗口可用区域；窗口与设备比例不同时，其余区域显示黑色。在画面内按住鼠标拖动可模拟滑动。主页及返回手势从画面对应边缘开始，并遵循设备的系统手势导航设置。

## iPhone / iPad 真机

### USB 观看镜像

用 USB 连接并解锁设备，在设备上信任此电脑。切换到 iOS 页，点 USB 真机的“查看镜像”，首次允许 macOS 采集权限；权限入口位于系统设置 → 隐私与安全性 → 相机。

观看镜像使用系统 AVFoundation 采集设备屏幕，无需 Apple 账号或设备端控制应用。需要从电脑操作设备时，连接“USB 操控”。

### USB 操控

1. 安装完整 Xcode，在 Xcode → Settings → Apple Accounts 登录自己的 Apple 账号。
2. 在程序“USB 操控：配置 Apple 账号”中点“重新检测”。单个团队自动使用；多个团队时选择用于设备签名的团队。
3. 在设备上开启开发者模式、信任电脑，并按提示信任开发者应用。验证需要正确的设备日期和可访问 Apple 服务的网络。
4. 点设备“USB 操控”行的“连接”。系统测试认证出现时，在设备上使用 Touch ID、Face ID 或密码完成。

Xcode 自动签名、注册设备并安装 WDA 控制组件；后续连接复用有效构建。签名有效期及可用设备受 Apple 账号权限限制，到期后需联网续签。账号密码与双重认证由 Xcode 处理。

### 点击、滑动、文字和虚拟按键

| 操作 | 行为与条件 |
|---|---|
| 点击 | 在画面内按下并松开鼠标；移动不超过 5 点且按住少于半秒 |
| 滑动 / 长按 | 从画面内开始拖动或按住至少半秒，松开后按轨迹和停顿时间重放；单次最长 30 秒 |
| 文字 | 先选中设备输入框，再输入或使用窗口文字栏发送；输入框是否接受取决于应用 |
| 返回 | 优先点击标准导航栏返回按钮，兼容 `BackButton` 标识；其次识别明确标注“返回／Back／上一页”等名称的按钮；无可用控件时尝试收起屏幕键盘 |
| 主页 | 从屏幕底部中央向上快速滑动并松开，由系统手势返回主屏幕 |
| 多任务 | 发送专用系统按键事件，打开应用切换界面 |
| 锁屏 / 唤醒 | 调用设备锁屏与唤醒接口 |
| 音量 | 真机窗口提供音量加减 |

iOS 没有 Android 式的全局返回键，未标注的自定义导航控件需要直接点击；多个返回控件同时可用时提示选择。系统弹窗会遮挡操作，应先处理设备上的提示。主页按钮发送底部上划手势，按当前界面方向换算坐标；多任务按钮发送专用系统按键事件。

滑动保留弯曲轨迹、移动速度和停顿，鼠标松开前设备尚未开始执行。从画面外开始的拖动和滚轮不发送触摸；从画面内拖出时坐标限制在边界。不额外识别边缘滑入或将拖动转换为主页／返回请求。窗口失焦、按 Esc、操作中旋转或调整画面尺寸会取消尚未提交的操作。

同一窗口一次执行一个控制操作，执行期间按键暂时禁用，画面点击会提示稍候；操作完成后再继续，避免积压过时指令。键盘连续输入按顺序合并为后续文字请求。程序不使用蓝牙控制。

## iOS 模拟器

安装完整 Xcode，选择开发者目录并下载 iOS Runtime，再为设备点“启动并连接”。首次编译 WDA，后续复用该模拟器的缓存；模拟器控制无需 Apple 账号。点击、滑动、长按、文字、返回、主页、多任务和锁屏与 USB 控制窗口一致，音量键仅在真机窗口提供。

## 实例、响应时间与故障定位

每个 Android 序列号对应独立 scrcpy 和 logcat 进程。每个 iOS 控制实例有独立 WDA 进程、缓存、本地端口、会话和日志；USB 观看镜像各自持有采集会话。同一设备已有控制会话时会提示先关闭该会话。关闭一个窗口只停止该实例；⌘1 打开设备列表，⌘Q 清理全部受管会话。

WDA 请求画面参数为 20 fps、50% 尺寸、55% JPEG 质量，实际帧率取决于设备。待显示帧只保留最新一帧，避免主线程繁忙时排队播放旧画面。点击以单次原生事件提交，坐标按屏幕缩放比例换算；自动化执行和画面采集仍会增加延迟。

全部日志位于 `~/Library/Logs/DeviceMirror/`。iOS 缓存位于 `~/Library/Caches/DeviceMirror/WDA/<UDID>/build-v3/`。控制日志中的 `CONTROL <接口> <耗时>ms HTTP <状态>` 表示 HTTP 请求耗时，不包含画面回传；日志不记录输入正文。连接失败时先检查窗口状态，再打开对应日志，具体处理见 [常见问题](../FAQ.md)。

## 构建与测试

构建需要 Apple Silicon Mac、完整 Xcode、命令行开发工具、Python 3.11+、Git、Homebrew，以及 Android SDK Platform 36 / Build Tools 36.1.0 和 Java 17+。文本输入组件默认使用 `~/Library/Android/sdk` 与 Android Studio 内置 Java；可通过 `ANDROID_HOME`、`JAVA_HOME` 指定位置。Android SDK 和 Java 仅在构建时使用。adb 从固定的 android-tools 源码编译，libusb 从固定源码编译为独立动态库；构建脚本校验源码归档。

在仓库根目录执行：

```sh
git submodule update --init --recursive
brew install pkgconf sdl3 cmake ninja protobuf brotli lz4 zstd googletest pcre2
./macos-launcher/build.sh
./macos-launcher/test.sh
python3 macos-launcher/verify-bundle.py "Device Mirror.app"
```

输出为仓库根目录的 `Device Mirror.app`；替换前需先退出正在运行的同路径应用。应用只有一个图形入口，内部辅助程序位于 `Contents/Helpers/`，动态库位于 `Contents/Frameworks/`。构建脚本从空目录组装，编译 scrcpy、原生控制服务和自有 Android 文本输入组件，打包 adb、WDA 源码、LGPL FFmpeg 动态库及对应源码、配置和许可证，最后验证签名。

`test.sh` 检查设备解析、命令参数、文字传输、超时清理、MJPEG 分包、iOS 点击、轨迹、停顿、长按与取消、Android 边缘坐标、日志进程隔离、USB 转发隔离、签名团队与描述文件，以及 WDA 打包时的版权保留和缓存更新。iOS 画面事件测试直接调用事件处理方法；Android 测试创建隐藏窗口，检查窄窗布局、原生鼠标坐标换算、本地输入隔离、一次按键一次提交与设备隔离；文本服务测试覆盖 Unicode、输入法恢复、缺少焦点、应用拒绝和结果不确定时禁止自动重发。测试应用禁止激活，不向桌面发送输入。

## 验证范围

截至 2026-11-06，既有设备验证与当前回归范围：

| 环境 | 已验证 |
|---|---|
| iPad Air 4 / iPadOS 26.3 | USB 控制组件：从“关于本机”返回“通用”；普通滑动改变列表可见内容 |
| iPhone 17 / iOS 26.5 模拟器 | 标准、自定义及网页返回后内容变化；根页面不会误点 Compose；UIKit 列表滚动；曲线轨迹、停顿、长按及横屏坐标 |
| iPad 真机、iPad Pro 13 英寸 / iOS 26.5 模拟器 | 0.5.6 主页底部上划：横屏与竖屏均从应用回到桌面；自动检测与指定前台应用均通过；多任务打开后可再次上划回到桌面 |
| iPad 与模拟器同时连接 | 独立端口及会话；关闭模拟器控制服务后 iPad 会话仍可访问 |
| 应用打包 | 一个图形 app 入口；动态库使用包内路径；搬移 app 后在不含 Homebrew / Python / Android SDK 的 PATH 下启动内部组件；深度签名校验 |
| Android | Android 16 真机已通过组件安装、设置搜索框中文／英文／表情单次提交、恢复原输入法并停用临时组件；自动检查覆盖原生点击坐标、单次按键提交、本地编辑隔离、无剪贴板命令、异常时输入法恢复、日志隔离及边缘坐标。新版投屏窗口的实际点击偏移与设备剪贴板内容保持仍需人工复验 |

0.5.0 测得 iPad 三次点击请求耗时约 353、459、512 ms，模拟器约 0.32–0.35 秒，均不含画面回传。当前环境的测量不代表其他设备或应用的延迟保证。系统弹窗需要先在设备上处理，它可能阻止导航按键。

导航回归检查需要独占的控制服务，并将设备停在“设置”中有标准返回按钮的详情页。检查会返回上一页、打开主页和多任务，通过页面结构断言结果，并将截图保存到指定目录：

```bash
python3 macos-launcher/tests/verify_ios_navigation.py /path/to/connection.json /path/to/evidence
```

主页手势检查会重启指定应用，验证横屏、竖屏下返回桌面及离开多任务界面，结束后恢复屏幕方向。需先处理设备上的系统弹窗；默认使用“设置”，也可通过 `--app` 指定已安装的应用：

```bash
python3 macos-launcher/tests/verify_ios_home.py /path/to/connection.json
```

模拟器的扩展检查会临时安装测试夹具，验证标准／自定义／网页返回和实际触摸轨迹，结束后卸载。测试夹具不随应用分发，也不打开 Mac 窗口：

```bash
python3 macos-launcher/tests/verify_ios_controls.py /path/to/connection.json <模拟器UDID> /path/to/evidence
```
