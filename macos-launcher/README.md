# Device Mirror 使用与构建

## 运行环境

打开 `Device Mirror.app`。应用约 65 MB，支持 Apple Silicon / macOS 26，内含 adb、scrcpy、原生 Swift 控制服务和动态库，可移到任意可读的本地目录使用。日常运行不依赖源码、Homebrew 或 Python。

iOS 实时操控要求 iOS / iPadOS 27 或以上及完整 Xcode 27 或以上，触摸和设备按键使用原生 CoreDevice / 模拟器 DTUHID 通道，文字、返回控件定位和旋转使用本机 XCTest 启动的 WDA 组件；真机还需要开发团队及设备测试认证。Android 和 iOS USB 观看镜像使用应用内组件及 macOS 系统功能。

构建产物采用本地签名。公开分发前需要完成 Developer ID 签名、公证及目标系统兼容性验证；Intel 与其他 macOS 版本尚未验证。

## Android

1. 用支持数据传输的 USB 线连接设备，开启 USB 调试，在设备上允许调试授权。
2. 在 Android 页选中设备，设置画质、帧率、音频及保持唤醒选项，再点“开始投屏”。这些选项在下次启动该设备时生效。

窗口顶部提供返回、主页、最近任务、旋转、音量、电源和通知按键。画面内支持点击、滑动、滚轮和键盘，每台设备独立设置，输入目标固定为该窗口所属设备。

“旋转”切换设备的横屏与竖屏，并锁定所选方向；需要自动旋转时，在设备快捷设置中恢复。当前应用需支持相应方向。返回、主页、最近任务、音量和电源按键支持按住：按下立即发送，半秒后发送长按与重复事件，松开或窗口失焦时释放；具体功能由设备系统和当前应用决定。

### 文字与按键

先点击设备中的输入框，再点投屏窗口顶部的“发送文本”，在面板中输入或粘贴文字后点“发送”；也可使用按键栏下方的文字栏。文字直接提交到当前输入框，支持中文和表情，保留设备剪贴板。首次发送时，应用自动安装约 13 KB 的 Device Mirror 文本输入组件；需要在设备上允许 USB 安装。每次发送临时切换到该组件，完成后恢复原输入法及启用状态。组件没有桌面入口、联网权限和剪贴板访问代码，命令接收仅允许 adb shell／系统权限。

普通键盘输入使用单一文字提交路径；本地文字栏和发送面板中的草稿只在点击“发送”时提交。文本与后续回车、退格、点击按同一设备的命令队列执行。安全输入框或应用自有编辑控件可能拒绝输入；未找到焦点时会提示先点击设备输入框。提交输入时使用“按键”菜单中的回车；该菜单也提供退格、Delete、Tab、Escape 和方向键。

### 日志

每次投屏自动保存 `mirror.log`。系统日志可在启动前勾选“投屏时记录系统日志（logcat）”，也可在设备列表选中活动设备后点“记录系统日志”或“停止记录”。

日志位于 `~/Library/Logs/DeviceMirror/android-<设备标识>-<会话标识>/`。每次录制生成独立的 `logcat-<标识>.log`，保留设备现有日志缓冲区。窗口“日志”定位运行日志，设备列表“此设备日志”打开会话目录。关闭投屏会停止该设备录制；持续录制会占用本机磁盘。

### 画面与滑动

画面保持设备比例，贴合窗口可用区域；窗口与设备比例不同时，其余区域显示黑色。在画面内按住鼠标拖动可模拟滑动。主页及返回手势从画面对应边缘开始，并遵循设备的系统手势导航设置。

## iPhone / iPad 真机

### USB 观看镜像

用 USB 连接并解锁设备，在设备上信任此电脑。切换到 iOS 页，点 USB 真机的“查看镜像”，首次允许 macOS 采集权限；权限入口位于系统设置 → 隐私与安全性 → 相机。

观看镜像使用系统 AVFoundation 采集设备屏幕，无需 Apple 账号或设备端控制应用。需要从电脑操作设备时，连接“USB 操控”。

### USB 操控

1. 确认设备运行 iOS / iPadOS 27 或以上，安装完整 Xcode 27 或以上，在 Xcode → Settings → Apple Accounts 登录自己的 Apple 账号。
2. 在程序“USB 操控：配置 Apple 账号”中点“重新检测”。单个团队自动使用；多个团队时选择用于设备签名的团队。
3. 在设备上开启开发者模式、信任电脑，并按提示信任开发者应用。验证需要正确的设备日期和可访问 Apple 服务的网络。
4. 点设备“USB 操控”行的“连接”。系统测试认证出现时，在设备上使用 Touch ID、Face ID 或密码完成。

Xcode 自动签名、注册设备并安装 WDA 控制组件；后续连接复用有效构建。签名有效期及可用设备受 Apple 账号权限限制，到期后需联网续签。账号密码与双重认证由 Xcode 处理。

### 点击、滑动、文字和虚拟按键

| 操作 | 行为与条件 |
|---|---|
| 点击 | 按下立即发送触摸，松开结束 |
| 滑动 / 长按 | 从画面内按下，实时发送移动；按住不动保持接触，松开结束；单次最长 30 秒 |
| 文字 | 先选中设备输入框，再输入或使用窗口文字栏发送；输入框是否接受取决于应用 |
| 返回 | 优先点击标准导航栏返回按钮，兼容 `BackButton` 标识；其次识别明确标注“返回／Back／上一页”等名称的按钮；无可用控件时尝试收起屏幕键盘 |
| 主页 | 从屏幕底部中央向上快速滑动并松开，由系统手势返回主屏幕 |
| 多任务 | 发送专用系统按键事件，打开应用切换界面 |
| 旋转 | 切换当前设备的横屏与竖屏；当前应用需支持目标方向 |
| 电源 | 实时发送电源键按下和松开，具体锁屏、唤醒或长按效果由系统决定 |
| 音量 | 真机窗口提供音量加减 |

iOS 没有 Android 式的全局返回键，未标注的自定义导航控件需要直接点击；多个返回控件同时可用时提示选择。系统弹窗会遮挡操作，应先处理设备上的提示。主页按钮发送底部上划手势，按当前界面方向换算坐标；多任务按钮发送专用系统按键事件。

触摸与按键在按下时发送，不积累轨迹等到松开后执行。移动最多按 120 Hz 排出最新位置，保留按下、最终位置与松开顺序；传输积压时停止控制并释放输入。画面外起点和滚轮不发送触摸；画面内拖出时坐标限制在边界。普通拖动不转换为导航命令。窗口失焦、Esc、画面旋转或尺寸变化会释放当前接触。

返回按钮先查询当前页面的返回控件位置，再发送实时触摸，查询本身有延迟。按住时保持该控件的触摸，松开后释放。主页按钮按下即开始底部上划，短按松开回主页，保持按住可停留在多任务手势中。多任务、电源和音量分别发送设备按键按下、松开，具体效果由系统决定。旋转按钮按一次执行一次。文字请求按设备顺序合并发送；传输失败后不自动重放已发送操作。

低于 27 或版本未知时，控制入口显示不支持，工具栏、触摸和文字输入不可用。真机使用“查看镜像”；模拟器可继续观看。原生服务在启动时重新查询设备版本，阻止使用过期列表绕过版本限制。

## iOS 模拟器

安装完整 Xcode 27 或以上并下载 iOS 27 或以上 Runtime，再为设备点“启动并连接”。首次编译 WDA，后续复用缓存；模拟器无需 Apple 账号。实时触摸通过模拟器 DTUHID 通道发送，返回定位、文字和旋转使用 WDA。低版本显示“观看”，控制禁用。

## 实例、响应时间与故障定位

每个 Android 序列号对应独立 scrcpy 和 logcat 进程。每个 iOS 控制实例有独立 WDA 进程、实时输入服务、媒体授权连接、缓存、本地端口、会话和日志；USB 观看镜像各自持有采集会话。同一设备已有控制会话时会提示先关闭该会话。关闭一个窗口只停止该实例；⌘1 打开设备列表，⌘Q 清理全部受管会话。

WDA 请求画面参数为 20 fps、50% 尺寸、55% JPEG 质量，实际帧率取决于设备。待显示帧只保留最新一帧，避免主线程繁忙时排队播放旧画面。触摸和设备按键经过持续原生输入通道发送，触摸开始时固定坐标方向。画面仍由 WDA 回传；文字、返回控件定位与旋转仍有自动化开销。实际延迟需在目标设备上测量。

全部日志位于 `~/Library/Logs/DeviceMirror/`。iOS 缓存位于 `~/Library/Caches/DeviceMirror/WDA/<UDID>/build-v3/`。控制日志中的 `CONTROL <接口> <耗时>ms HTTP <状态>` 表示 HTTP 请求耗时，不包含画面回传；日志不记录输入正文。连接失败时先检查窗口状态，再打开对应日志，具体处理见 [常见问题](../FAQ.md)。

## 构建与测试

构建需要 Apple Silicon Mac、完整 Xcode、命令行开发工具、Python 3.11+、Git、Homebrew，以及 Android SDK Platform 36 / Build Tools 36.1.0 和 Java 17+。文本输入组件默认使用 `~/Library/Android/sdk` 与 Android Studio 内置 Java；可通过 `ANDROID_HOME`、`JAVA_HOME` 指定位置。Android SDK 和 Java 仅在构建时使用。adb 从固定的 android-tools 源码编译，libusb 从固定源码编译为独立动态库；构建脚本校验源码归档。

在仓库根目录执行：

```sh
git submodule update --init --recursive
brew install pkgconf sdl3 cmake ninja protobuf brotli lz4 zstd googletest pcre2
./macos-launcher/build.sh
./macos-launcher/test.sh
python3 macos-launcher/verify-bundle.py "Device Mirror.app"
```

输出为仓库根目录的 `Device Mirror.app`；替换前需先退出正在运行的同路径应用。应用只有一个图形入口，内部辅助程序位于 `Contents/Helpers/`，动态库位于 `Contents/Frameworks/`。构建脚本从空目录组装，从源码编译 scrcpy 客户端与服务端、原生控制服务和自有 Android 文本输入组件，打包 adb、WDA 源码、LGPL FFmpeg 动态库及对应源码、配置和许可证，最后验证签名。

`verify-bundle.py` 在独立端口启动全新的 adb 服务并查询设备，避免已运行的系统 adb 掩盖内置服务的启动故障。

`test.sh` 检查设备解析、命令参数、文字传输、超时清理、MJPEG 分包、iOS 实时按下／移动／松开、取消、版本门槛、有界移动队列和 HID 报文、Android 边缘坐标、日志进程隔离、USB 转发隔离、签名团队与描述文件，以及 WDA 打包时的版权保留和缓存更新。iOS 画面事件测试直接调用事件处理方法；Android 测试创建隐藏窗口，检查窄窗布局、原生鼠标坐标换算、本地输入隔离、一次按键一次提交与设备隔离；文本服务测试覆盖 Unicode、输入法恢复、缺少焦点、应用拒绝和结果不确定时禁止自动重发。虚拟按键检查覆盖即时按下／松开、单次提交、取消、Android 重复事件、窗口失焦释放及实例隔离。测试应用禁止激活，不向桌面发送输入。

## 验证范围

截至 2026-11-06：

| 环境 | 验证结果 |
|---|---|
| macOS 26.6.2 / Xcode 27.1 | 所需 CoreDevice、CoreSimulator、AVConference 接口可加载；Swift 与原生输入服务可编译 |
| iPad Air 4 / iPadOS 26.3 | 原生服务拒绝启用控制并返回需要 27+；不发送触摸或设备按键 |
| iOS 26.5 模拟器 | 拒绝启用控制；设备列表标记仅观看 |
| app 兼容性检查 | 98 个原生组件的 arm64 架构与 macOS 26.0 部署目标；独立端口首次启动 adb；只读包与含空格路径；无 Xcode 时仍可列举可用设备；精简 PATH 下运行；签名及压缩包解压后检查 |
| 本地回归 | 按下与移动在松开前交给传输层；取消和坐标变化释放；不支持设备不发送输入；移动合并保留顺序；58 字节 HID、主页边缘位和 XPC 整数类型检查 |
| Android | 保留既有实时触摸、独立日志和文本组件；本地坐标、输入、队列与实例隔离回归 |

当前没有 iOS 27 真机或 27 Runtime，持续触摸、长按、主页、多任务及横屏映射尚未完成 27 端到端实测。接口存在、报文检查和编译通过不能代替设备响应验证。旧版 XCTest 重放链路的测量不适用于当前输入通道。

Android 控制检查会在指定设备临时安装测试应用，验证按键长按标记、横竖屏切换及画面控件长按；结束后卸载测试应用并恢复旋转设置：

```bash
python3 macos-launcher/tests/verify_android_controls.py "Device Mirror.app" <Android序列号>
```
